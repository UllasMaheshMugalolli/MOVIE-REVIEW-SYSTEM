1. Frontend Architecture Overview

🏗️ Technology Stack

  • Framework: Next.js 16.0.1 (React-based framework with SSR/SSG capabilities)
  • React Version: 19.2.0
  • Routing: Next.js file-based routing system
  • State Management: React Hooks (useState, useEffect)
  • Styling: Custom CSS with CSS Variables for theming
  • Authentication: JWT (JSON Web Tokens) stored in localStorage
  • HTTP Client: Native Fetch API

🎯 Key Design Principles

  1. Component-Based Architecture: Reusable components (Navbar, Footer, MovieCard) used across pages
  2. Client-Side Authentication: JWT tokens parsed on the client to determine user permissions
  3. Protected Routes: useEffect hooks check authentication status and redirect unauthorized users
  4. API Communication: Centralized API URL configuration via environment variables
  5. Responsive Design: CSS-based responsive layouts for mobile and desktop
  6. Dark Theme: Modern dark UI with blue accent colors
💡 Why Next.js?
Next.js provides automatic code splitting, optimized page loading, file-based routing, and excellent developer experience. It's perfect for this project as it allows both static and dynamic pages while maintaining simplicity.

export default function App({ Component, pageProps }) {

    <>

      </Head>
      <Component {...pageProps} />

What's Happening:

  • Component: Represents the active page component based on the current route
  • pageProps: Props passed to the page (empty in our case, but useful for SSR/SSG)

  • Global CSS: Imported here to apply styles across all pages
🔍 Why This Matters:
_app.js runs on every page navigation. It's the perfect place for global imports, authentication wrappers, or context providers. We keep it minimal since we handle auth per-page.

🌍 Environment Variables

The frontend uses .env.local to configure the API URL:

NEXT_PUBLIC_API_URL=http://localhost:4000

This is accessed in pages as:

const apiUrl = process.env.NEXT_PUBLIC_API_URL || 'http://localhost:4000'
⚠️ Important: In Next.js, environment variables must be prefixed with NEXT_PUBLIC_ to be accessible in the browser. Variables without this prefix are only available server-side.

4. Utility Functions

🔐 utils/auth.js - Authentication Helpers

Purpose: Provides reusable functions to extract user information from JWT tokens.

// Check if user is admin
export const isUserAdmin = () => {
  try {
    const token = localStorage.getItem('token');
    if (!token) return false;
    
    const payload = JSON.parse(atob(token.split('.')[1]));
    return payload.is_admin === true;
  } catch (e) {
    return false;
  }
};

// Get full user info from token
export const getUserInfo = () => {
  try {
    const token = localStorage.getItem('token');
    if (!token) return null;
    
    const payload = JSON.parse(atob(token.split('.')[1]));
    return {
      user_id: payload.user_id,
      username: payload.username,
      is_admin: payload.is_admin || false
    };
  } catch (e) {
    return null;
  }
};

How JWT Decoding Works:

  1. JWT Structure: A JWT has 3 parts separated by dots: header.payload.signature
  2. token.split('.')[1]: Extracts the payload (middle part)
  3. atob(): Decodes the Base64-encoded payload
  4. JSON.parse(): Converts the JSON string to a JavaScript object

🎯 Use Cases:

  • isUserAdmin(): Used in Navbar to show/hide Admin link
  • getUserInfo(): Used in admin pages to verify permissions before rendering
  • Error Handling: Try-catch ensures corrupted tokens don't crash the app
🔒 Security Note:
JWT tokens are decoded on the client, but the actual authorization happens on the backend. The frontend only uses this to show/hide UI elements. The backend validates the token signature for every protected API call.

🔑 Login Page (login.js)

Route: /login

Purpose: User authentication page.

Form Fields:

  • Email (type: email, required)
  • Password (type: password, required)

Submit Handler:

const handleSubmit = async (e) => {
  e.preventDefault(); // Prevent page reload
  setMessage(''); // Clear previous messages
  
  try {
    const res = await fetch(`${apiUrl}/api/auth/login`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ email, password })
    });
    
    const data = await res.json();
    if (!res.ok) throw new Error(data.error || 'Login failed');
    
    // Store token in localStorage
    localStorage.setItem('token', data.token);
    
    // Redirect to homepage
    router.push('/');
  } catch (err) {
    setMessage(err.message);
  }
};

Success Flow:

  1. User submits email and password
  2. Frontend sends POST request to /api/auth/login
  3. Backend validates credentials and returns JWT token
  4. Frontend stores token in localStorage
  5. User is redirected to homepage
🔐 Token Storage:
JWT is stored in localStorage with key 'token'. This persists across page reloads but is cleared when user logs out or clears browser data.

useEffect(() => {
  const token = localStorage.getItem('token');

  setIsAdmin(true);

Why CSS Variables?

  • Consistency: One source of truth for colors
  • Easy Theming: Change one value, updates everywhere
  • Maintainability: No hardcoded hex values scattered in code
  • Performance: Browser-native, no JS required

10. Application Flow

🔄 User Journey - New User

  1. Visit Homepage: Sees landing hero with welcome message
  2. Click Sign Up: Navigates to /signup
  3. Fill Registration Form: Username, email, password
  4. Submit Form: POST to /api/auth/register
  5. Backend Creates User: Hashes password, stores in database
  6. Receive JWT: Token returned and stored in localStorage
  7. Redirect to Homepage: Now logged in, sees quick stats
  8. Browse Movies: Can view movies, rate, and see details

🔄 User Journey - Existing User

  1. Visit Homepage: Sees login/signup options
  2. Click Sign In: Navigates to /login
  3. Enter Credentials: Email and password
  4. Backend Validates: Checks password hash
  5. Receive JWT: Token contains user_id, username, is_admin
  6. Token Stored: localStorage keeps user logged in
  7. Access Protected Pages: Can browse movies, submit ratings

🔄 Admin Journey

  1. Login as Admin: JWT contains is_admin: true
  2. See Admin Link: Navbar shows "⚙️ Admin"
  3. Access Dashboard: Navigate to /admin
  4. Choose Operation: Manage movies, persons, etc.
  5. Perform CRUD: Add/Edit/Delete entities
  6. Backend Validates: authenticateAdmin middleware checks token
  7. Data Persisted: Changes saved to database
  8. UI Updates: Tables refresh showing new data
